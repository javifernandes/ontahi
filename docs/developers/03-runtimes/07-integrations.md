# Integrations by concern

Choose an integration for the responsibility your application needs. The same
technology can appear in several rows because each concern has its own runtime
contract, setup, and evidence.

| Concern                        | Where to compare capabilities and configure an adapter                                                                                                                                                                                                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Query and command storage      | [Storage adapters](02-storage-adapters.md) and the [storage matrix](05-adapter-capability-matrix.md#data-graph) cover Core in-memory, PostgreSQL, MySQL, and Supabase.                                                                                                                                                                          |
| Durable Operations             | Compare [execution configurations](05-adapter-capability-matrix.md#durable-execution-configurations) and the [conformance matrix](../../durable-operation-conformance.md) for PostgreSQL, Vercel Workflow, and LangGraph. Start with the [runtime setup recipes](../02-core-concepts/09-durable-operations.md#configure-the-execution-runtime). |
| Events                         | The [Event Runtime matrix](05-adapter-capability-matrix.md#event-runtime) covers live and durable delivery. The [Events chapter](../02-core-concepts/10-events.md) explains subscriptions, delivery, and their guarantees.                                                                                                                      |
| HTTP, WebSocket, and ingress   | The [host and transport matrix](05-adapter-capability-matrix.md#hosts-ingress-and-transport) and the [transport chapter](03-transport-and-http-ingress.md) cover Express and Next.js.                                                                                                                                                           |
| Authentication                 | [Authentication and Principals](04-authentication-and-principals.md) explains how a host supplies trusted identity and invocation context.                                                                                                                                                                                                      |
| Observability                  | [Observability](06-observability.md) shows the OpenTelemetry adapter and OTLP export recipes for local SigNoz and Axiom.                                                                                                                                                                                                                        |
| Model execution                | [AI Operations](../05-further-directions/02-ai-operations.md) explains how model-backed Operations fit into Ontahí. [Observability](06-observability.md#read-an-ontahí-trace) describes model attempt spans.                                                                                                                                    |
| Browser clients and inspection | [Browser Client and Projection](../04-reflection-and-clients/02-browser-client-and-projection.md), [Reflection and Explorer](../04-reflection-and-clients/01-reflection-and-explorer.md), and [Devtools](../04-reflection-and-clients/03-semantic-console-and-devtools.md).                                                                     |

Use the linked matrix and provider notes for guarantees such as checkpoint recovery,
Interaction or Event-wait resumption, and ownership of claims and leases.
An OTLP destination is a host export choice and has its own setup requirements.
