# Ontahi 1.0.0-alpha.12 — candidate guide

Status: prepared for the generated release PR; not a publication announcement.

All fifteen packages advance together. The Changesets release workflow owns the exact versions,
package changelogs and publication. This guide summarizes the final candidate, rather than the
order in which its individual implementation slices landed.

## What is in this candidate

| Area                    | Delivered surface                                                                                                                                                       | Deliberate boundary                                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Semantic Console        | TS-like/declarative reads, shared authoring preference, rich scalar editors, capability-aware completion, Visual/JSON results and source-backed ordering/limits         | No Commands or Operation invocation syntax                                                                                              |
| Selection factories     | Pure named `by` input/output contracts, composition, contextual Relation navigation, reflection and browser codegen                                                     | Existing locators remain supported; no external resolver or implicit fetch                                                              |
| Classified Entities     | Fixed-enum variants, classified read roots and contextual targets, canonical base identity, direct `existingRef(Variant)` participants                                  | Experimental read surface; no variant writes, transitions, standalone generated variant exports or deferred classified Operation inputs |
| Contextual providers    | In-memory, PostgreSQL, MySQL and native Supabase/PostgREST membership; Graph Read v2 with per-hop grants and scopes                                                     | Physical provider requirements apply; no contextual Commands, v1 fallback or contextual observation                                     |
| Runtime and React       | Unified Fetch transport, WebSocket multiplexing/cancellation, query observations and normalized query-cache reconciliation                                              | Hosts still own ingress, authentication, cache lifetime and production change feeds                                                     |
| Devtools                | Semantic Activity, Cache groups/reference navigation, bounded opt-in entity history, Console Observe/Stop for supported v1 many reads                                   | Local debugging, not persisted versioning, an audit log or all React observers                                                          |
| Storage and cardinality | MySQL/shared SQL, ordered relations, exact-one checks before shaping                                                                                                    | `one` cannot hide duplicates with a limit; `one + limit(0)` is rejected                                                                 |
| Consumer compatibility  | Transitive/recursive Value projection, wire schemas separate from server transforms, composite native Ref inputs, receiver binding and Operation union result inference | Arbitrary callbacks never become browser code; unsupported schemas produce diagnostics                                                  |

## Upgrading a host

Pin every direct `@ontahi/*` dependency to the same published version and commit the resulting
lockfile with the manifests. Regenerate clients and task artifacts, check generated drift, then run
host types, authorization-sensitive integration tests and a production build. Do not commit local
rehearsal tarballs or substitute a floating `alpha`/`latest` tag for an exact pin.

For hosts upgrading from alpha.11, review the transport default (`/runtime`), custom transports
accepting metadata as well as read requests, exact-one/count behavior and the new provider
requirements. Custom Supabase clients must preserve exact count metadata and scoped embedded
filters. A storage package upgrade does not install FKs, relation RPCs or migrations automatically.

For older hosts such as BookOps's alpha.3 baseline, the upgrade includes already-published changes:
replace authored Operation `inputRefs` with schema-native participants, review portable conditions
and input processing, and migrate call sites, generated contracts, transport wiring and cache keys
together. Keep genuinely scalar URL inputs scalar where their not-found/access-shell behavior
requires it. `existingRef` is a materialization choice, not a mechanical replacement for every id.
The [BookOps inventory](../research/release-readiness-bookops-2026-09.md) records that wider migration.

## Candidate evidence and publication gate

The main-inclusive rehearsal uses source `28a41a5` and its integrity-recorded fifteen-package
manifest. It passed package builds/types/lint, 2,606 package tests, Todo's 70 tests and Classroom's
12 tests, plus clean-consumer artifacts and offline npm dry-run. The subsequent Explorer fixture
and Supabase connection-lifecycle corrections are test-only; documentation changes do not change
published runtime behavior.

BookOps consumed only that candidate's tarballs for reached Ontahi packages and passed 968 unit,
47 integration, 17 pgTAP and 23 Chromium Storybook cases, codegen drift, types, lint and a clean
production build. Storybook coverage is not a full authenticated browser-to-database journey.
Tracked registry pins remain unchanged until publication. Exact manifests and rehearsal boundaries
are recorded in the inventory; these locally packed alpha.11-labelled bytes are not registry alpha.11.

Compatibility changes must reach main before the bot refreshes the release PR. Fresh CI and
security/quality checks must pass on that refreshed candidate before merging it to publish.
Local rehearsal success is not permission to bypass a failing release gate.
